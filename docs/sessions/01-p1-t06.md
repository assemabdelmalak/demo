Part A, super admin:
- Record on the session when a TOTP or backup-code check succeeds (`session.twoFactorVerifiedAt`). "Remember this device" must not count.
- An admin policy for routes: signed in, email in `SUPER_ADMIN_EMAILS`, email verified, two-factor enabled, and a TOTP check on this session within the last 12 hours; never a PIN session. Non-admin gets 403; an admin without a fresh TOTP check gets 403 `TWO_FACTOR_REQUIRED`.
- `GET /v1/me` gains `isSuperAdmin`; the console shows the admin shell only then.
- `/v1/admin/orgs` list, read and `PATCH` (status, plan) on a separate admin database pool (`DATABASE_URL_ADMIN`, `withAdmin`) that nothing else uses. Every admin action goes through the audit seam.
- Bull Board at `/v1/admin/queues` behind the same check.

Part B, staff devices and PIN:
- A new migration with a `SECURITY DEFINER` function to find a device by its token hash before a tenant is known (pinned `search_path`, executable by `app_runtime` only). Update the catalog tests in packages/db/src/rls.int.test.ts.
- Register a device (manager): random token, only its SHA-256 stored, set as an HttpOnly cookie scoped to the API host only. List and revoke; revoking deletes the device's sessions.
- Set and remove a member's PIN (staff and kitchen only): argon2id over an HMAC with a pepper derived from `BETTER_AUTH_SECRET`; never returned.
- PIN switch: needs the device cookie; staff or kitchen member of the device's organisation; failures counted in Valkey before verifying; 5 failures lock for 5 minutes, 15 in a day disable the PIN until a manager sets a new one; fails closed without Valkey; every failure looks the same. Success creates a 12-hour session marked as a PIN session, bound to the device.
- A PIN session: hard 12-hour limit enforced on every request, confined to the device's organisation and to staff or kitchen permissions, needs the device cookie on every request, dies when the device is revoked, and may only call get-session and sign-out under `/v1/auth/*`.

Tests: every rule above, as integration tests in apps/api/test, plus unit tests for the pure parts. Keep all existing tests green.
